**Authorization:** IP-2A R10 documentation and review of existing IP1-B03 evidence only. No new probe, implementation, schema work, test, dependency or runtime integration is authorized.

**Baseline:** `2561888f717b1ae8fdfd2611495d21111c987d8c` (`implementation/ip-2a-r10-b03-qualification-plan`).

## 4. Cancellation and worker evidence

### Cooperative parser cancellation

The asynchronous R3 experiment had a separate thread set an atomic cancellation request. The parser-owning thread observed it in the descriptor read callback during intentionally slowed reads, returned failure, produced no partial success, closed once, and performed no later read after observation. A cleanup-timed cancellation similarly returned failure and closed once. These are cooperative checkpoints, not a maximum-latency guarantee.

The approved plan requires prompt cancellation, cancellation checks during reads/callbacks, no partial model/output, and measured latency on qualified targets. The 250 ms value in `RESOURCE-LIMITS.md` is a candidate evaluation target, not an approved hard deadline. No R10 decision sets or relaxes a deadline.

### CPU-bound work and disposable worker

R3's disposable child was repeatedly parsing a synthetic 8,402,951-byte input. The parent successfully sent SIGTERM and reaped it; the recorded one-run values were 35.630 ms child CPU, 9,764,864 bytes Darwin peak RSS and 264 μs kill-to-reap. This demonstrates only that this child in this research configuration could be terminated and reaped. It is classified as **PROCESS-ISOLATION EXPERIMENT**, not product architecture, general cancellation guarantee, memory cap, or service-level deadline. R10 makes no worker-isolation decision.

No parser-context operation was called concurrently from the cancellation thread. Existing evidence does not establish thread safety of cross-thread `xmlStopParser` or other context operations; do not infer it.

## 8. Recommended next action (not authorized here)

No new probe is needed to support this R10 classification. The smallest next action with the highest immediate value is an independent security review of this control/evidence matrix and the original R2/R3 manifest against IP-2 plan §§3–4 and 11. The review should determine whether any hard memory/CPU bound is mandatory and whether the exact candidate loader/configuration evidence is sufficient for a narrowed residual-risk recommendation. If it identifies a specific missing empirical case, authorize one bounded experiment named to that gap. Do not start broad adversarial testing or worker architecture work by default.

This was a recommendation at the R10 handoff. R12 subsequently reviewed the existing evidence and recorded **INSUFFICIENT EVIDENCE — FURTHER QUALIFICATION REQUIRED**; it selected no architecture. The separately authorized R13 probe later produced host-specific CPU/watchdog evidence and partial address-space containment evidence, but did not close B03 or pass IP-2A. See [`IP-2A-R12-RESOURCE-CONTAINMENT-DECISION.md`](IP-2A-R12-RESOURCE-CONTAINMENT-DECISION.md) and [`IP-2A-R13-WORKER-RESOURCE-FEASIBILITY.md`](IP-2A-R13-WORKER-RESOURCE-FEASIBILITY.md).

R14 subsequently identifies an isolated worker as a **candidate requiring qualification**, not selected production architecture. R13 supports only host-specific CPU-time enforcement, parent watchdog termination/reap, and limiting new mappings near a very large existing address-space baseline; it does not demonstrate hard RSS containment. The R10 classifications and open B03 status remain unchanged. See [`IP-2A-R14-CONTAINMENT-ARCHITECTURE-REVIEW.md`](IP-2A-R14-CONTAINMENT-ARCHITECTURE-REVIEW.md).
