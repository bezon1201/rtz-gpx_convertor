## 5. Parser-security recovery package (B03)

The minimum remaining package is a **qualification decision**, not another broad exploratory run:

1. Preserve the R2/R3 identity and configuration as candidate evidence: exact libxml2 source release/hash, static linkage check, parser flags/resource loader/DOCTYPE handling, synthetic case identities and outcomes.
2. For each resource, record the enforcement point and evidence class:
   - bounded descriptor read and limit+1: hard bound on bytes supplied by that read boundary, not parser RSS;
   - depth/element/text/attribute counters: cooperative parser/application callback limits, observed after some parser allocation;
   - CPU/time and memory/RSS: observed metrics only in the current harness, not hard per-conversion bounds;
   - read/callback cancellation: cooperative checkpoints, not a deadline;
   - worker termination/reaping: disposable research observation, not selected production architecture or an application cancellation guarantee.
3. Review whether the approved contract requires hard process CPU/memory ceilings or whether explicit limits plus reviewed residual-risk disposition satisfy it. The approved numeric proposals are not approved constants.
4. Identify only the missing cases that change this classification: supported candidate OS/runtime behavior and, if needed, targeted adversarial or schema-validator workload evidence. Any new probe requires separate scoped authorization.
5. Close B03 only when approved security requirements, enforceable limits/known residuals, candidate runtime and supported-configuration evidence, and independent review jointly satisfy the IP-2A acceptance and blocker criteria. Otherwise retain OPEN/PARTIAL.

**Isolated parser decision:** R3 demonstrates that a disposable child can be terminated and reaped during tested CPU-bound work, but it does not establish production suitability, protocol, memory/CPU caps, signed packaging, or supported-OS behavior. Whether isolation is necessary is a separate architecture decision after the requirement classification in item 3. R9 selects no architecture and creates no worker implementation.

- **REQUIRES EXTERNAL CONFIRMATION:** exact CIRM RTZ 1.2 artifact linkage to IEC PAS 61174-1:2021 and resolution of the `IEC PAS 6XXXX` placeholder; authoritative exact artifact/hash mapping.
